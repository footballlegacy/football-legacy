# FL-MSQ4R4TZ presentation and performance audit

Date: 2026-08-12

Source: user-supplied `football-legacy-playtest-FL-MSQ4R4TZ.json`

Build logged: `0.174`, requested `fl-v2`, effective authority `fl-v2-live`

## Scope and result

This audit covers only the tunnel, kick-off wait, perceived frame rate, manual switching, requested FIFA-style instant replay, backflip, celebration selection delay, ball drag, and the end-of-log breakdown. It does not claim that a note proves the cause of what the tester saw.

The log is strong enough to confirm several timing and routing behaviours, but it cannot measure rendered frame rate. A web-to-desktop migration is therefore not justified by this file. The highest-confidence bounded work is the tunnel opening, kick-off timing, a delayed roaming celebration-selection phase, backflip direction/speed, and an isolated pause-only replay-review mode. Manual switching and ball drag need better incident telemetry or a reproducible visual capture before tuning.

## Performance decision

`frame` must not be reported as rendered FPS. At frame 11425 the match has advanced about 190.4 seconds of fixed-step simulation, while the wall-clock session includes long pauses used to write notes. Sparse event timestamps cannot show how many frames were displayed, dropped, or caught up. The only defensible conclusion is: poor frame rate was perceived, but its magnitude and cause are unmeasured.

A desktop wrapper would still need to render the same WebGL scene, so platform migration should follow, not replace, profiling. The first performance acceptance run should use the same match seed, stadium, DPR/resolution, camera, and crowd settings across browsers, with a short captured interval covering live play and the late repeated-contact sequence.

## Change order and safety gates

1. Instrument performance and the ambiguous switch/drag incidents before tuning them.
2. Make the tunnel opening and kick-off latency changes independently; browser-check each.
3. Add the shared eight-second roaming selection phase, then calibrate backflip direction/duration inside that isolated celebration route.
4. Design instant replay as pause-only state, reusing immutable snapshots but not automatic-replay lifecycle state.
5. Re-run existing controller, pause-timer, replay, kick-off legality, and presentation regressions. Add focused assertions described above only with the corresponding implementation.

No runtime file was changed by this audit. No regression test was added because a test against the present values would preserve behaviour the playtest explicitly rejects, while a performance test based on this log would encode an invalid FPS inference.
